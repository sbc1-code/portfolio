RELEASE DECISION · 01 SEP 2026

Hold v0.3; fix escalation and unsupported-claim behavior

The agent is clear and on-tone in routine interactions, but two failures create unacceptable operational risk. Shipping now would trade speed for preventable rework and customer distrust.

What the run says

  • 6 of 8 scenarios pass.
  • Routine status and scheduling flows are reliable.
  • A missing-record case triggers an unsupported certainty claim.
  • A time-sensitive medical-record request fails to escalate.

Smallest safe fix

  1. Add an evidence-required rule before status claims.
  2. Route urgent or ambiguous medical-record requests to a human queue.
  3. Rerun the two failures plus adjacent edge cases.
  4. Ship only after blocker count reaches zero.
